# Mock builder (`agent.build`, offline)

Rule-based, deterministic handler for LLM purpose `agent.build`, registered in `../mock-llm.ts` so
`LLM_PROVIDER=mock` builds real projects end to end. It is a template-based code generator, **not a
model**: every generated file starts with `Generated by Forge mock builder (rule-based, offline)` and
every final reply says so.

## How it works

`handler.ts` is a state machine over the conversation that `BuildAgent` / `runToolLoop` pass in.
Tool call ids encode the phase (`mb-<phase>[-<sig>]-<n>`), so the next step follows from what was
already done and what the tool results said:

| Round | Steps |
| ----- | ----- |
| build | `list_files` (+ `read_file` of a referenced OpenAPI doc) → `write_file` × N → setup `run_command` (deps, `drizzle-kit generate`, ruff) → post files (custom migrations) → typecheck/lint `run_command` + `run_tests` → one auto-fix + re-verify on failure → summary |
| fix / strategy / replan | parse gate failures → `forge:public` markers (only when `spec.auth` is false or for health/docs routes), Next.js session checks, RLS SQL from the gate's proposed fix, `eslint --fix` / ruff → re-verify; anything else (or a repeat of an earlier fix) is reported as "needs a real model" without tool calls |
| design | contrast fixes in `tokens.css` (WCAG 7:1 text, 4.5:1 muted/button) |
| website / follow-up / review | verify only, honest reply |

## Generators (`generate.ts`)

| Template | Generator | Output |
| -------- | --------- | ------ |
| `nextjs` + `spec.auth` | `gen-nextjs-auth.ts` | app-kit Better Auth + Drizzle: tables with `owner_id` + `pgPolicy` RLS (incl. linked policies for the auth tables) → `drizzle-kit generate`; zod validation; server actions with `requireUser()` inside `withUser()`; list/create/edit/delete pages; booking rules (unique slot index + `btree_gist` exclusion constraint), pipeline enums (check constraint + board), progress |
| `nextjs` (no auth), `vite-react-ts` | `gen-web-local.ts` | zod entity modules + `localStorageStore` repository + accessible generic manager; CSV dashboard (RFC 4180 parser, monthly revenue / top products SVG charts, fictional `public/sample-sales.csv`) |
| `hono-api` | `gen-hono.ts` | `zValidator` CRUD routers, `InMemoryRepository`, OpenAPI 3.1 from zod, bearer token when `spec.auth` |
| `fastapi` | `gen-fastapi.ts` | strict Pydantic models, routers, `InMemoryRepository`, pytest |
| `expo` | `gen-expo.ts` | logic modules, streaks/progress, token-styled screen, vitest |
| OpenAPI in spec | `gen-openapi.ts` | `@forge/integrations` `generateTypedClient` client, server-side key, validated GET proxy routes, explorer |

## Limitations

- Only the spec's data model is implemented (CRUD + the domain rules above); free-text follow-ups,
  reviewer findings and most design notes are not interpreted.
- In-memory / localStorage persistence for non-auth apps and APIs (stated in the UI and summary).
- No roles: shared entities in auth apps are readable by all signed-in users, editable by their creator.
